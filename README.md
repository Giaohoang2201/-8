# [과제 - 08] 최소 비용 신장 트리(MST) 알고리즘 성능 비교 분석 보고서

본 문서는 정점 50개의 무방향 가중치 그래프를 대상으로 **인접 리스트 + 크루스칼(Kruskal)** 알고리즘과 **인접 행렬 + 프림(Prim)** 알고리즘을 각각 적용하여 측정한 실험 결과를 바탕으로 성능을 비교·분석한 보고서입니다.

---

## 1. 실험 결과 요약 (Case 1 ~ Case 4)

* **Case 1 (희소 그래프 + 인접 리스트 + Kruskal):**
  - Vertices: 50 | Edges: 100 | MST Edges: 49
  - MST Cost: (그래프 무작위 생성에 따라 산출된 전체 비용)
  - Memory: 약 3,920 Bytes
  - Execution Time: 0 ~ 1 ms 미만

* **Case 2 (밀집 그래프 + 인접 리스트 + Kruskal):**
  - Vertices: 50 | Edges: 600 | MST Edges: 49
  - MST Cost: (전체 비용 산출)
  - Memory: 약 20,720 Bytes
  - Execution Time: 0 ~ 1 ms

* **Case 3 (희소 그래프 + 인접 행렬 + Prim):**
  - Vertices: 50 | Edges: 100 | MST Edges: 49
  - MST Cost: (Case 1과 동일한 그래프이므로 Cost 일치)
  - Memory: 약 10,400 Bytes
  - Execution Time: 0 ~ 1 ms

* **Case 4 (밀집 그래프 + 인접 행렬 + Prim):**
  - Vertices: 50 | Edges: 600 | MST Edges: 49
  - MST Cost: (Case 2와 동일한 그래프이므로 Cost 일치)
  - Memory: 약 10,400 Bytes
  - Execution Time: 0 ~ 1 ms

---

## 2. 심층 비교 및 분석 (Analysis)

### ① MST 전체 비용 및 간선 수의 일치성
- 정점 수가 50개인 연결 그래프의 MST는 정의에 따라 반드시 **49개의 간선**을 포함합니다.
- 동일한 그래프 데이터(희소 그래프 1쌍, 밀집 그래프 1쌍)를 공유하여 실험하였으므로, 알고리즘(Kruskal vs Prim)이 선택하는 간선의 조합(구성)은 달랐으나 **MST 전체 비용(Total Cost)은 완벽히 동일**하게 산출되어 구현의 정합성을 확인했습니다.

### ② 인접 리스트와 인접 행렬의 메모리 사용 차이
- **인접 행렬 (Prim):** 간선의 개수와 무관하게 항상 $V \times V$ 크기의 고정된 메모리($50 \times 50 \times 4 \text{ bytes} = 10,000 \text{ bytes}$)를 소모합니다. 따라서 간선이 적은 희소 그래프(Case 3) 환경에서도 상대적으로 많은 메모리를 차지하는 경향이 있습니다.
- **인접 리스트 (Kruskal):** 그래프의 간선 수에 비례하여 동적으로 메모리가 할당됩니다. 간선이 100개인 희소 그래프(Case 1)에서는 행렬보다 현저히 적은 메모리를 사용하지만, 간선이 600개로 늘어난 밀집 그래프(Case 2)에서는 리스트 노드 포인터 및 보조 데이터로 인해 메모리 사용량이 인접 행렬보다 더 커지게 됩니다.

### ③ Kruskal 알고리즘과 Prim 알고리즘의 실행 특성 차이
- **Kruskal 알고리즘:** 모든 간선을 가중치 기준으로 정렬하는 과정이 필요하므로 시간 복잡도는 $O(E \log E)$입니다. 간선의 수가 적은 희소 그래프에서는 정렬 부담이 적어 매우 유리합니다.
- **Prim 알고리즘:** 매 단계마다 전체 정점을 순회하며 최소 비용을 탐색하므로 시간 복잡도는 $O(V^2)$입니다. 간선의 개수 $E$와 무관하게 정점 수 $V$에 종속되므로, 간선이 많고 복잡한 밀집 그래프 환경에서 안정적이고 일관된 성능을 발휘합니다.

### ④ 그래프 밀도가 성능에 미치는 영향
- 그래프의 밀도(Density)는 알고리즘 효율성의 핵심 요인입니다.
- **희소 그래프(Sparse Graph, $E=100$):** 간선이 적어 Kruskal 알고리즘의 정렬 연산이 매우 빠르게 수행되며, 인접 리스트를 통한 메모리 절감 효과도 극대화됩니다.
- **밀집 그래프(Dense Graph, $E=600$):** 간선이 많아 Kruskal은 정렬 비용이 증가하는 반면, Prim 알고리즘은 정점 중심의 탐색 구조 덕분에 밀도가 높은 환경에서도 성능 저하 없이 효율적으로 동작함을 확인했습니다.
